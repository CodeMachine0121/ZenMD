最近在選桌面框架，把**取捨**攤開來看，結論跟我一開始想的相反。

## 一句話結論

拿**安裝包大小**換**文字輸入的正確性**。對一個每天用來寫中文的工具，這個交易划算到不需要猶豫。

## 兩者的架構事實

| | Electron | Tauri |
| :--- | :--- | :--- |
| 渲染引擎 | 自帶 Chromium，三平台同一版 | 各平台自己的 webview |
| macOS 上實際跑的 | Chromium | WKWebView（WebKit） |
| 安裝包 | 100 MB 以上 | 10 MB 級 |
| 輸入法行為 | **一套** | **三套** |

## 為什麼引擎一致這麼重要

打英文是「按一鍵、出一字」。打中文不是——你按 `ㄊ` `ㄞ` `ˊ`，螢幕先出現未定的組字內容，選字之後才產生真正的字元。

> 這段「組字中」的狀態，是英文輸入完全不存在的第三種狀態。
> 編輯器若在這段期間去動文件內容，輸入法的狀態機就會被打斷。

而 WebKit 上有一個查得到的 bug：

```ts
// 軟換行 + 組字，正是出問題的組合
editor.dispatch({
  changes: { from, to, insert },
  // 組字中一律不進來
  filter: () => !view.composing,
})
```
